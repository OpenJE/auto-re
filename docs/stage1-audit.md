## Ambiguities / Issues

1. **`analysis/packet.rs` — Destination crate unclear**: The `FunctionAnalysisPacket` design (typed IDs, content hashes, call graph neighbors, deterministic serialization) is architecturally sound, but it's unclear whether it should live in `autore-coordinator` (as a work-item schema) or `autore-provider` (as an input schema for provider capabilities). **Recommendation**: Discuss with team — the packet is a work-unit design, so `autore-coordinator` is the better fit, but the provider may need equivalent input types.

2. **`error.rs` — Umbrella error fate**: The `ModelProvider`, `AnalysisBackend`, and `Worker` error variants will move to their respective crate's error types. At the end of migration, `error.rs` either becomes a thin re-export crate or disappears entirely. **Recommendation**: Keep as umbrella until migration is complete, then evaluate.

3. **`storage/repositories/task.rs` leasing SQL**: The atomic leasing logic (`BEGIN IMMEDIATE` + `INSERT OR REPLACE INTO leases`) is proven concurrent-safe by tests. The new work-item lifecycle through `ApplicationCommand` will need equivalent concurrency safety in the SQLite-backed handler. **Recommendation**: Reference this file when implementing `LeaseWorkItem`/`RenewWorkLease`/`CompleteWorkItem` handlers in `autore-app`.

4. **`cli/mod.rs` interim state**: The new CLI (Todo 50) does not ship until Wave 11. Between Wave 1 and Wave 11, the old CLI must continue working for testing. **Recommendation**: Keep old CLI subcommands until Wave 11, then replace.
