IMPLEMENTATION SUMMARY
----------------------
1. PackageValidationError enum with 13 variants (Io, Toml, SchemaVersion, PackageId,
   EntrypointMissing, EntrypointNotContained, SymlinkEscape, ContentHashMismatch,
   ProtocolRange, CapabilityEmpty, CapabilityInvalid, ConfigurationSchemaInvalid, VersionParse)

2. PackageManifest struct with validated fields: schema_version, package_id, version (semver),
   content_hash (BLAKE3 bytes), entrypoint, protocol_range, capabilities (proto CapabilityDescriptor),
   max_concurrency, configuration_schema (JSON Schema bytes)

3. PackageInstallationIntent struct returned to coordinator with manifest + package_root + executable_path

4. ProviderPackageDiscovery struct reading from project.auto-re/provider_roots.toml (optional)
   with fallback to <project_dir>/providers/

5. validate_package() function implementing full validation pipeline:
   - TOML parse via intermediate RawManifest struct
   - schema_version == 1
   - package_id regex ^[a-z0-9-]+\.[a-z0-9-]+$ (LazyLock compiled)
   - semver version parse
   - entrypoint exists and canonical path within package root
   - content hash: walk files (exclude manifest.toml, reject symlinks), BLAKE3 each,
     sort by relative path, feed (path, hash) pairs into final BLAKE3 hash
   - protocol range includes coordinator version 1
   - capabilities non-empty, each with non-empty id, semver version (major >= 1),
     valid JSON Schema request_schema/response_schema
   - configuration_schema valid JSON Schema

6. compute_content_hash() public helper for creating package fixtures
